# CrewAI Travel Planner

A small command-line travel-planning example built with [CrewAI](https://www.crewai.com/). Enter a city and receive a concise, AI-generated list of three places to visit. The project includes a hosted-LLM version and a local [Ollama](https://ollama.com/) version.

> **Note:** This is a prompt-driven demo, not a live travel service. It does not use maps, browsing, or location data to verify opening hours, distances, route feasibility, or current conditions. Confirm details before travelling.

## Features

- Interactive city input from the terminal.
- CrewAI `Agent`, `Task`, and `Crew` orchestration.
- A **hosted-model** example in `travel_planner.py`, configured through environment variables.
- A **local-model** example in `ollama/travel_planner_ollama.py`, configured for Ollama and `qwen2.5:latest`.
- Explicit output constraints to keep recommendations short and consistently formatted.

## How it works

Both scripts ask for a city, provide a CrewAI agent with a travel-planning role and context, then run one task and print the model's response. The default script describes a three-stop, half-day walking loop for time-conscious solo travellers. The Ollama version asks for three concise place recommendations and builds its crew in `build_crew()` before running it from `main()`.

The recommendations are generated by the configured language model. Neither script calls a mapping, search, or booking service, so geographical closeness and other factual details are not independently checked.

## Prerequisites

- Python 3.10 or later (recommended).
- A supported CrewAI installation.
- For the hosted-model script: an API key for the model provider configured for your CrewAI environment.
- For the Ollama script: [Ollama installed and running](https://ollama.com/download), with the configured model downloaded.

## Setup

Clone the repository and create an isolated Python environment:

```bash
git clone https://github.com/Karthickbalakrishnan/crewai-travel-planner.git
cd crewai-travel-planner
python -m venv .venv
```

Activate it:

```bash
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Install the packages used by the examples:

```bash
python -m pip install --upgrade pip
python -m pip install crewai python-dotenv
```

`python-dotenv` is used by `travel_planner.py` to load a local `.env` file. The Ollama script uses CrewAI's `LLM` integration and does not load `.env` itself.

## Run

### Hosted model

Set the API key expected by your CrewAI model/provider configuration. The script calls `load_dotenv()`, so you can create a `.env` file in the project directory, for example:

```dotenv
OPENAI_API_KEY=your_api_key_here
```

Keep `.env` private; do not commit real credentials. Then run:

```bash
python travel_planner.py
```

Enter a city when prompted. The script prints CrewAI's result. The selected model is determined by the installed CrewAI/provider configuration; although the source comment mentions `MODEL`, this script does not read a `MODEL` environment variable directly.

### Local model with Ollama

Start Ollama and download the model configured in the script:

```bash
ollama pull qwen2.5:latest
```

Then, with Ollama available at `http://localhost:11434`, run:

```bash
python ollama/travel_planner_ollama.py
```

The script prompts for a city and prints the raw result. To use another Ollama model or server, edit `LLM(model=..., base_url=...)` in `ollama/travel_planner_ollama.py`.

## Configuration

| Script | Model configuration | Credentials / service |
| --- | --- | --- |
| `travel_planner.py` | CrewAI's provider defaults; no model is explicitly set in the script. | Loads environment variables from `.env`; provide the credential required by your provider (the source comment names `OPENAI_API_KEY`). |
| `ollama/travel_planner_ollama.py` | `ollama/qwen2.5:latest` | Local Ollama server at `http://localhost:11434`; no cloud API key is configured in this script. |

To adjust the recommendations, change the agent's `role`, `goal`, or `backstory`, and the task's `description` or `expected_output`. Preserve the explicit count and format requirements if consistent output is important.

## Troubleshooting

- **Missing API key or provider error:** Check that the right provider credential is set in `.env` or the process environment, and verify that the provider/model configuration supported by your CrewAI version is in place.
- **Ollama connection refused:** Start Ollama and confirm it is listening at the `base_url` in `ollama/travel_planner_ollama.py`.
- **Ollama model not found:** Run `ollama pull qwen2.5:latest`, or change the configured model to one you have installed.
- **Unexpected output format:** LLMs may not obey every instruction exactly. Adjust the prompt or add output validation if strict formatting is required.

## Limitations

- Recommendations may be inaccurate, outdated, or unsuitable; verify independently.
- The scripts do not retrieve current travel information or validate the route on a map.
- The default script's “walking loop” is a prompt objective, not a route calculated from geographic data.
- There is no dependency lockfile, test suite, or structured output validation yet.
